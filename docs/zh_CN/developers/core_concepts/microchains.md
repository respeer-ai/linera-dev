# 微链

本节介绍Linera协议的核心构建模块——微链。更正式的阐述请参阅[白皮书](https://linera.io/whitepaper)。

## 背景

`微链`是由区块组成的链式结构，用于记录共享状态的连续变更。后续文档中， _链_ 与 _微链_ 将视为等同概念。Linera微链在保留区块链核心理念的同时，具备以下关键特性：

- 在Linera网络中，任意数量的微链可共存于同一验证节点集群，并共享同等安全级别。创建新微链仅需在现有链上执行一笔交易。

-   微链中新区块的提议任务可由验证节点或终端用户（实质是其钱包）承担，具体取决于链的配置。具体而言，根据授权主体不同，微链可分为 _单所有者_ 、 _多所有者_ 或 _公共_ 三种类型。

## 跨链消息

在传统单区块链网络中，每个交易均可访问应用的全部执行状态。而Linera网络采用分层状态管理机制，应用状态分散存储于多个微链中，且任一微链的状态仅由其自身区块决定。

跨链消息传递是不同微链之间实现异步通信的机制。该方法允许将应用与数据分布式部署于多链架构，从而提升系统扩展性。当某条链上的应用向自身在另一条链上的实例发送消息时，将生成跨链请求。此类请求通过验证节点内部网络的远程过程调用（RPC）实现，确保每个请求仅执行一次。

系统不会立即修改目标链，而是先将消息存入目标链的**收件箱**。当目标链的所有者未来创建新区块时，可从当前收件箱中选择若干消息引用至新区块。此过程将执行选定消息，并将其操作应用于链上状态。

以下示例展示了一组链通过连续区块实现异步消息交互的流程。

```ignore
                               ┌───┐     ┌───┐     ┌───┐
                       Chain A │   ├────►│   ├────►│   │
                               └───┘     └───┘     └───┘
                                                     ▲
                                           ┌─────────┘
                                           │
                               ┌───┐     ┌─┴─┐     ┌───┐
                       Chain B │   ├────►│   ├────►│   │
                               └───┘     └─┬─┘     └───┘
                                           │         ▲
                                           │         │
                                           ▼         │
                               ┌───┐     ┌───┐     ┌─┴─┐
                       Chain C │   ├────►│   ├────►│   │
                               └───┘     └───┘     └───┘
```

Linera协议允许接收方丢弃消息，但不可更改两条链间通信队列中已选消息的顺序。若某条已选消息执行失败，钱包在提议接收方区块时将自动拒绝该消息。当前Linera客户端的实现策略为：尽可能从收件箱中选取最多消息，且除非消息执行失败，否则不会主动丢弃。

## 链所有权语义

活动链可设有一至多个所有者。若链的所有者数量为零，则该链将被永久停用。

在Linera协议中，验证节点确保系统 _安全性_ ：每条链的每个高度仅允许存在唯一区块。

而 _链的活性_（即实际新增区块的能力）则依赖于所有者。根据不同的应用场景需求，Linera设计了多种轮次类型与所有者模型：

- 首先为可选的 _快速_ 轮次：_超级所有者_ 可提议区块，这些区块通过极低延迟机制确认，适用于无竞争的单所有者链场景。
- 随后是 _多领导者轮次_ ：所有 _常规所有者_ 均可提议区块。即使存在偶尔的临时争用（例如使用多个设备的单一所有者，或多人低频使用同一链），该模式仍能有效运行。
- 最后是 _单领导者轮次_ ：为每个常规链所有者分配专属时间槽，期间仅允许其提议新区块，不受其他所有者提案干扰。此模式特别适合多用户同时尝试提交区块的高并发场景。

多领导者轮次的数量可配置：对于活动水平波动的链，当所有多领导者轮次在高争用期间均失败时，系统可动态切换至单领导者模式。对于频繁出现多所有者高活跃度的链，可将多领导者轮次数量设为0。

有关链的开启/关闭操作详情及示例，请参阅钱包部分的[链管理](../../../zh_CN/developers/core_concepts/wallets.md#opening-a-chain)章节。
