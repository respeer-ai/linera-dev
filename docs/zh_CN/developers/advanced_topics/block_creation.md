# 创建新区块

> 在Linera中，提议区块的职责与验证区块的任务是相互分离的。

尽管所有链的验证方式都相同，但Linera协议根据新区块生成方式的不同，定义了多种类型的链。

- 最简单且延迟最低的链类型被称为 _单所有_ 者链。

- Linera链的其他类型（当前在SDK中尚未支持）包括 _多用户链_ 和 _公共链_（详见[白皮书](https://linera.io/whitepaper)了解更多信息）。

> 对于大多数链类型（_公共链_ 除外），Linera验证者无需相互交换消息。

相反，链所有者（即`Linera`客户端）的钱包通过提议区块并主动向验证者提供额外所需数据来推动系统运行。例如，客户端命令（如`transfer`、`publish-bytecode`或`open-chain`）会执行多个步骤来追加包含代币转账、应用发布或链创建操作的区块：

- Linera客户端会创建一个新区块，其中包含预期的操作及新收到的消息（如有）。该区块还会包含最新区块的哈希值以标识其父区块。随后，客户端会将此新区块发送至所有验证者。

- 验证者会对区块进行验证，即检查区块是否符合上述条件，并向客户端发送加密签名以表明其投票支持追加该新区块。但前提是他们此前未对同一高度的其他区块投过票！

- 理想情况下，客户端会收到所有验证者的投票，但只需达到法定票数（例如三分之二）即可形成"证书"，证明该区块已获确认。随后，客户端会将此证书发送给所有验证者。

- 验证者会“执行”区块：他们通过应用所有消息和操作来更新各自对链当前最新状态的视图。如果该区块生成了跨链消息，验证者会将这些消息发送至对应的工作节点。

为确保区块中的每条传入消息确实由其他链发送，验证者在第二步投票时，只有当该区块已执行​​发送该消息的原始区块​​时才会投赞成票。然而，若验证者收到一份针对某区块的有效证书（即使该区块包含其尚未见过的消息），他们仍会接受并 _执行_ 该区块。这是因为证书证明大多数其他验证者已见过该消息，因此其内容必定正确。

在单所有者链中，客户端必须经过精心设计，以确保其​​不得提议同一高度的多个区块​​。否则，链可能会陷入停滞：一旦两个冲突区块各自获得足够验证者的签名，将无法为任一区块收集到法定票数。

未来，我们预计大多数用户即使作为链的唯一所有者，也会选择使用 _多用户链_ 。多用户链设置了两个确认步骤（而非一个），但​​不会意外导致链无法扩展​​。此外，这类链允许用户将某些管理任务委托给第三方（例如在验证者因重新配置而发生变更时的epoch过渡阶段提供协助）。
